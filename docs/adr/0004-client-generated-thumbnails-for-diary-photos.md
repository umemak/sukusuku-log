# クライアント側サムネイル生成と R2 格納アーキテクチャ

思い出日記の写真グリッド一覧において、通信量削減と高速な画像表示を実現するため、写真アップロード時にブラウザ側で原版（長辺1600px）とサムネイル（長辺320px）の双方を生成して R2 に格納し、一覧表示時はサムネイル、詳細時は原版を配信する構成を採用した。

## Considered Options

- **Cloudflare Image Resizing / 有料CDN動的リサイズ**: 原版のみ保存してオンデマンドで縮小可能だが、無料枠運用の制約を超えて追加課金（Proプラン/アドオン）が発生する。
- **Workers サーバー側での WASM 画像縮小**: アップロード時に Workers 内で WASM 等を用いて縮小処理を行うが、Workers の CPU 実行時間制限・メモリ制限を圧迫し、処理失敗やレイテンシ悪化のリスクがある。
- **原版のみ保存し CSS 縮小表示**: 実装は最もシンプルだが、グリッド一覧で数十枚の原版（計10MB〜30MB超）が同時ダウンロードされ、モバイル回線での表示速度と端末負荷が著しく悪化する。

## Consequences

- サーバーの CPU や追加インフラ費用を一切消費せず、端末側の処理能力を活用して高速かつ経済的なサムネイル配信が可能になる。
- サムネイル未作成の過去データについては、サムネイル取得時に 404 となった場合またはキー不在時に原版へフォールバックすることで、過去データの全件変換バッチなしに互換性を維持する。
